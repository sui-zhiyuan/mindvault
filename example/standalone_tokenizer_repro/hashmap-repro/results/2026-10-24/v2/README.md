# v2 数据集：统一二进制重测

## 为什么重测

早期测量用的查询循环是 `while k < n { get(&k); k += stride }`；后来加入 `--query-file/--query-repeat/--capacity` 后，查询循环改为迭代 `Vec<usize>`。两者在 ARM 上的代码生成不同：n=4096 时旧版 41.8 cyc/q、新版 36.0 cyc/q（x86 33.2 → 32.2）。为了让所有数字可比，这里用**同一份新二进制**（rustc 1.98.0）重测关键点。

## 结果（n=78,960，reserve，3 个独立进程 × 15 reps）

| hasher | ARM cyc/q | x86 cyc/q（估） | 比值 |
|---|---:|---:|---:|
| std | 68.0 | 48.9 | 1.39 |
| mix | 26.1 | 15.5 | 1.68 |
| identity | 8.7 | 6.5 | 1.33 |

token-like（52,640 次 get）：ARM 66.8 / x86 45.9 cyc/q（1.46）。

## n 扫描（std, reserve）

| n | 表约 | ARM | x86 | 比值 |
|---:|---:|---:|---:|---:|
| 4,096 | 136 KiB | 36.0 | 32.5 | **1.11** |
| 16,384 | 544 KiB | 38.9 | 34.1 | 1.14 |
| 32,768 | 1.1 MiB | 45.4 | 40.8 | 1.11 |
| 49,152 | 1.1 MiB | 50.2 | 42.9 | 1.17 |
| 65,536 | 2.2 MiB | 66.1 | 47.6 | **1.39** |
| 131,072 | 4.4 MiB | 75.0 | 51.5 | **1.46** |

拐点在 1.1 MiB 与 2.2 MiB 之间，与 ARM 每核 L2 约 1.3 MiB 吻合。

## 读法

- **小表几乎持平**（1.11×）：核心 hash/probe 代码本身差别不大。
- 表超出 L2 后差距升到 1.4–1.5×，且随 footprint 增长；与负载因子扫描（0.70→0.95 平坦、低负载大表变差）一致。
- 与依赖加载延迟曲线（两机 L1/L2 相当、2 MiB 处 cycles 几乎相同）合起来看，差距更像是**多流随机访问下的 L2/L3/TLB 行为**，而不是单次 load 延迟或哈希算术。

## 局限

- x86 周期仍是「墙钟 × 4.45 GHz」估算，±3%；
- 3 个进程、单机、热表；
- 未分离 L2/L3 与 TLB 的独立贡献。

原始数据：`arm/`、`x86/`。
