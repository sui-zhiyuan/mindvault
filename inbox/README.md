# 待整理收件箱（inbox）

> 更新：2026-10-16

## 简介

还没成体系、不属于任何主题的记录，先进这里；整理后再提升为 `docs/` 下的正式笔记。

本目录**不是书的一部分**：位于 mdBook 的 `src = docs` 之外，不进 `docs/SUMMARY.md`，也不要求套用知识笔记模板。它的作用只有一个 —— 让「随手记」和「正式笔记」分开，避免草稿污染书的目录与搜索索引。

## 与其它目录的分工

| 目录 | 放什么 |
|---|---|
| `inbox/` | 零散、未定主题、待整理的记录（**本目录**） |
| `docs/` | 整理好的正式笔记：进 `SUMMARY.md`、按模板写、进书的搜索索引 |
| `research/<topic>/` | 已成一个主题、处于研究/过程阶段的长稿（如 `research/virtualization/`） |
| `work-records/<topic>/` | 工作交付记录（含多模型产出对比等） |
| `ideas/` | 零散想法 / 灵感（还没成为"记录"的） |
| `reports/`、`heavy/`、`example/` | 生成的 HTML/PPT 等大文件、复现样例 |

## 命名与格式约定

- **一条记录一个文件**：`YYYY-MM-DD-<主题>.md`，例如 `2026-10-16-lvm-pv-release.md`；不要写成一个大流水账。
- 文件头三行元信息，方便日后判断该去哪：

  ```markdown
  > 日期：2026-10-16
  > 来源：与 DSH 的问答 session / 某文档 / 现场排查
  > 待整理：可并入「LVM 运维」笔记 / 主题未定
  ```

- 正文随便写：命令、原始输出、结论、疑问都可以，**不求结构、不求完备**。
- **不放二进制/大文件**：PPT、HTML、压缩包放 `heavy/`，生成的报告放 `reports/`。
- 不放敏感信息（私钥/口令/公网 IP/内部主机名），规则同 `AGENTS.md`。

## 整理（提升）流程

1. 选定去向：`docs/<topic>/<note>.md`（若是新主题，同时补该目录 `README.md` 与 `docs/SUMMARY.md` 条目），或并入 `research/<topic>/`。
2. 提升时套用 `AGENTS.md` 里的知识笔记模板（简介 / 术语列表 / 核心内容 / 延伸 / Q&A / 参考资料）。
3. 用 `git mv inbox/<file> docs/<topic>/<note>.md` 保留历史；整理完的条目即从 inbox 消失。
4. 粒度随意：一条可拆成多篇笔记，多条也可合并成一篇。
