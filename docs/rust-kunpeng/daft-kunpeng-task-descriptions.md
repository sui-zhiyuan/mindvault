# 任务 1：Daft UDF 能力优化（对应模板 1）

【需求描述】
1、优化Daft的UDF功能，从而提升视频、文本、图像、音频产线的性能。
2、具体优化范围覆盖四条支线：在 UDF 执行链路上减少 Rust 与 Python 之间的跨界转换以及 UDF 各阶段之间的数据搬运，减少中间物化与拷贝；在算子与编译层推进文本归一化算子融合、MinHash 的 SVE2 向量化以及面向 950 SVE 宽度的 LLVM 自动向量化；在基准产线 `volc_operator_sim` 中选取覆盖文本、视频、图像、音频、PDF 与自动驾驶多传感器的 6 条代表产线进行端到端优化，目标优化 5%；在生态集成上适配鲲鹏亲和多模态算子库与 Lance 算子下推。

【业务背景与价值】
现有的产线流程中，使用 Python 定义处理步骤，通过 Daft 的 UDF 调用该步骤处理视频、文本、图像、音频。UDF 执行过程中，Rust 与 Python 之间、UDF 各阶段之间存在大量数据搬运、格式转换与重复的中间物化，已成为制约产线吞吐的关键因素。本任务围绕 Daft 的 UDF 执行链路优化：减少跨界次数、中间物化与拷贝；通过文本归一化算子融合、面向鲲鹏 950 的 SVE/SVE2 向量化与 LLVM 自动向量化，把高频文本处理下沉为引擎内实现；集成鲲鹏亲和多模态算子库，并把 Lance 的视频解码与抽帧算子下推到数据源侧。优化收益在基准产线 `volc_operator_sim` 上端到端验证，从而提升 Daft UDF 的执行效率与视频、文本、图像、音频产线的性能，支撑 950 自提升 5%、950V200 与 9755 性能比提升 5% 的验收标准。

【Actor】
生态开发者

【验收场景】
环境配套
os版本： openeuler 24.03 SP3
daft版本： 0.7.5
文本数据集：Common Crawl/RedPajama-Data
图像数据集：LAION-5B/LAION-Art
视频数据集：InternVid
音频数据集：WenetSpeech

【验收方式】
1、基于原始版本的Daft运行视频产线项目，获得原始版Daft产线的吞吐量及响应时间
2、基于优化后的Daft运行视频产线项目，获得优化后Daft产线的吞吐量及相应实现

【验收标准】
验收质量属性：技术项目
1、自提升：950优化前后对比，性能提升5%
2、950 vs 9755：950V200与9755性能比提升5%

【交付计划】
交付件：穿刺源码交付（代码合入GitCode/蓝区代码仓）

# 任务 2 子任务描述（对应模板 2）

## 模板 2 原条目：减少 UDF 过程中的跨界损耗（任务 2 总纲）

【标题】
减少UDF过程中的跨界损耗

【背景】
使用Daft的UDF功能时，执行引擎内部存在大量跨边界的数据移动和格式转换：
1. Rust ↔ Python 边界转换：Rust中的数据类型需要转化为Python UDF能处理的对象，Python UDF的返回值需要变为Daft的内部列数据
2. UDF阶段之间的数据传递

【描述】
通过 减少跨界次数、减少中间物化，减少拷贝，从而降低UDF过程中数据传输开销，从而提升产线性能

【输入】
950V200、9755标准性能验收环境和视频、文本、图像、音频产线性能用例

【输出】
950V200与9755性能对比结果

## 任务 2-1：文本归一化融合、SVE2 向量化与 LLVM SVE path 优化

【标题】
文本归一化融合、MinHash SVE2 向量化与 LLVM SVE path 优化

【背景】
LLM 预处理（Pipeline B）链路中，文本归一化由 `regexp_replace` → `lower` → `regexp_replace` 三个独立步骤
串联完成，每步都会生成中间结构并产生一次列数据物化与传递；MinHash 签名计算以标量循环方式逐个更新签名位置，
循环次数多、内存访问密集，未利用鲲鹏 950 的 SVE 向量能力；编译器侧默认自动向量化未针对 950 的 SVE 宽度调优，
SVE 计算模块的能力未被充分利用。

【描述】
围绕 LLM 预处理（Pipeline B：文本归一化 + MinHash 去重）链路推进三项优化，逐项降低文本链路的计算与数据移动开销。

第一项为文本归一化优化：把 `regexp_replace`、`lower`、`regexp_replace` 三个连续步骤融合为一个算子，
减少中间结构生成与中间列数据的物化；交付仓库为 pipeline B 文本归一化优化（Daft，AtomGit），
预期在 LLM 预处理上相对提升 3.3%、自提升 28%。

第二项为 MinHash 替换 SVE2 实现：以向量化方式更新多个签名位置，并对最多 8 个哈希值做批处理，
减少循环次数和内存访问；交付仓库为 pipeline B 性能优化（文本归一化融合、SVE2 文本向量化、SVE2 MinHash，
Daft，AtomGit），预期在 LLM 预处理上相对提升预估 5%、自提升 35%。

第三项为 LLVM 优化 path 参数优化：优化 LLVM 层面自动向量化，针对 950 指定 SVE 宽度（SVE256），
充分利用 SVE 计算模块能力；交付仓库为 target Kunpeng 950 with SVE256（Daft，AtomGit），
预期在 LLM 预处理上相对提升 3.2%。

所有 aarch64 侧改动需经受运行时 CPU feature 检测门控，在不支持 SVE 的平台上回退到通用路径。

【输入】
950V200、9755 标准性能验收环境；Pipeline B（LLM 预处理：文本归一化 + MinHash 去重）性能用例与文本数据集
（Common Crawl / RedPajama-Data）。

【输出】
1、三个优化项的 Daft 侧源码交付（合入 GitCode / 蓝区代码仓）
2、950V200 与 9755 上 LLM 预处理链路的性能对比结果（相对提升 / 自提升）

## 任务 2-2：基准产线（`volc_operator_sim`）端到端优化

【标题】
优化基准产线 `volc_operator_sim` 中的代表产线，覆盖文本 / 视频 / 图像 / 音频 / PDF / 自动驾驶多传感器，目标优化 5%

【背景】
UDF 与执行链路层面的单项优化需要在真实产线上验证收益。基准产线 `volc_operator_sim` 汇集了文本、视频、
图像、音频、PDF 与自动驾驶多传感器六类模态的代表性数据预处理链路，是衡量端到端性能的基准；
当前这些产线在 950 上仍有约 5% 的优化空间尚未释放。

【描述】
在基准产线 `volc_operator_sim` 中选取 6 条产线进行端到端优化，目标优化 5%。其中，文本模态选取网页语料清洗入湖
（`pipeline_text_fineweb_full_min`）；视频模态选取长视频场景切分（基模 QA 产线，`video_scene_split_etl`）；
图像模态选取图像策管全链路（`pipeline_image_full_min`）；音频模态选取 ASR 音频准备
（`audio_asr_prep_canonical`）；PDF 模态选取 PDF 文档解析向量化（`pipeline_pdf_full_min`）；
自动驾驶模态选取多传感器索引（`pipeline_ad_nuscenes_min`）。
优化手段以任务 2-1、2-3、2-4 的成果为主（算子融合、SVE 向量化、算子库集成、算子下推），
按产线逐个定位瓶颈算子并回归验证。

【输入】
950V200、9755 标准性能验收环境；上述 6 条产线的性能用例（定义见 `volc_operator_sim` 的 `tasks/*.json`）
及对应模态数据集。

【输出】
1、各产线优化前后的吞吐量、响应时间对比结果
2、950V200 与 9755 的性能对比结果
3、Daft 侧优化源码交付（合入 GitCode / 蓝区代码仓）

## 任务 2-3：Daft 适配鲲鹏亲和多模态算子库

【标题】
Daft 适配鲲鹏亲和多模态算子库

【背景】
鲲鹏多模态算子库以独立仓库模式交付，该库面向鲲鹏平台对图像、视频、音频等多模态处理算子做了亲和实现。
Daft 侧当前的多模态处理主要依赖通用 Python 生态库，缺少与鲲鹏亲和多模态算子库的对接通道，
无法直接获得硬件亲和优化带来的收益。

【描述】
在 Daft 侧完成鲲鹏亲和多模态算子库的集成适配：以独立仓库模式引入该算子库，在 Daft 的算子层
（含 UDF 执行路径）封装可被物理计划调用的接口，并保证接口不可用时回退到原有实现；
目标是在文本 / 图像 / 视频 / 音频产线中把通用实现替换为鲲鹏亲和实现，降低多模态算子的处理耗时。

【输入】
鲲鹏多模态算子库（独立仓库交付件）、Daft 0.7.x 源码、950V200 / 9755 标准性能验收环境、
视频 / 文本 / 图像 / 音频产线性能用例。

【输出】
1、Daft 侧集成适配源码（合入 GitCode / 蓝区代码仓）
2、集成前后多模态产线的性能对比结果

## 任务 2-4：Daft 适配 Lance 算子下推

【标题】
Daft 适配 Lance 算子下推

【背景】
Lance 作为 AI 原生列式湖存储，具备在数据源侧实现视频解码与抽帧的能力。当前视频解码、抽帧等步骤在
Daft 侧（或 Python UDF 中）执行，视频数据需要从存储层搬到计算层再做解码，存在大量跨边界数据搬运
与格式转换开销。

【描述】
Lance 实现数据源侧的视频解码和抽帧能力，Daft 侧完成适配，将算子下推到 Daft 中，
使解码与抽帧尽可能贴近数据源执行，减少数据搬运与中间物化，从而降低视频产线的 I/O 与转换开销。

【输入】
Lance 侧算子下推能力（独立交付件）、Daft 0.7.x 源码、950V200 / 9755 标准性能验收环境、
视频产线性能用例与视频数据集（InternVid）。

【输出】
1、Lance 侧能力与 Daft 侧适配源码（合入 GitCode / 蓝区代码仓）
2、算子下推前后视频产线的吞吐量与 I/O 开销对比结果
