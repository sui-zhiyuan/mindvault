# Daft Kunpeng 设计描述：多模态算子库与 Lance 算子下推

> 更新：2026-02-12

## 简介

本文以 `rust-kunpeng-design.md` 中的「## 模板」为固定框架，把「## 输入 1」「## 输入 2」两份需求要点分别展开为一份**完整描述**。模板中的【】项目名称与格式逐字保留，各模块下填充对应输入的实质内容（输入未给出的模块由模板框架 + 输入原文表述推导补全）。

两份描述的定位：

- **描述一** 面向 **鲲鹏亲和多模态算子库** 在 Daft 侧的集成适配（算子层 / UDF 路径封装 + 不可用回退）。
- **描述二** 面向 **Lance 数据源侧视频解码与抽帧的算子下推**（减少跨边界搬运与中间物化）。

Prerequisites: 环境按鲲鹏 950 / AMD 9755 标准性能验收环境配置；Daft 源码取自 GitCode 社区。Related: [Daft Kunpeng 性能优化设计](daft-kunpeng-perf-design-spec.md) / [Daft Kunpeng 总体设计需求分析](daft-kunpeng-overall-design.md)

## 核心内容

### 描述一：Daft 适配鲲鹏亲和多模态算子库

【简要描述】

在 Daft 侧完成鲲鹏亲和多模态算子库的集成适配：以独立仓库模式引入该算子库，在 Daft 的算子层（含 UDF 执行路径）封装可被物理计划调用的接口，并保证接口不可用时回退到原有实现；目标是在视频 / 文本 / 图像 / 音频 / PDF / 智能驾驶 / LLM 预处理产线中，把通用 Python 生态实现替换为鲲鹏亲和实现，降低多模态算子的处理耗时。

【Actor】

生态开发者

【前置条件】

1. 环境配置按照鲲鹏 950 / AMD 9755 标准性能验收环境配置指南配置完成。
2. 从 GitCode 社区获取 Daft 0.7.2 源码，部署到鲲鹏 950、9755 上。
3. 以独立仓库模式获取鲲鹏多模态算子库交付件，按其 Readme 安装依赖并完成构建。
4. 参考社区项目 Readme 安装 Daft 软件依赖，编译 Daft 代码，生成 wheel 文件。
5. 用户安装 Daft wheel 与算子库交付件，并准备视频 / 文本 / 图像 / 音频 / PDF / 智能驾驶 / LLM 预处理产线的性能用例数据集。

【最小保证】

从 GitCode 获取的 Daft 源码，以及独立仓库模式的鲲鹏多模态算子库交付件，均可在 950 环境中正常安装部署成功。

【成功保证】

用户可以正常执行各多模态产线的测试用例与基准测试用例，并获得正确的执行时间；Daft 侧集成适配源码合入 GitCode / 蓝区代码仓。

【触发事件】

无

【主成功场景】

用户成功编译 Daft，并部署至鲲鹏 950 环境。
用户安装鲲鹏多模态算子库交付件，Daft 通过算子层封装接口（含 UDF 执行路径）成功调用鲲鹏亲和算子。
用户调用 Daft，正常执行视频 / 文本 / 图像 / 音频 / PDF / 智能驾驶 / LLM 预处理产线的测试用例。
统计执行时间，950 上算子库调用前后对比，可观察到多模态算子处理耗时下降的自提升。
接口不可用时，Daft 自动回退到原有通用实现，用例仍可正常执行。

【扩展场景】

算子库接口部分能力缺失或加载失败时，按算子粒度回退到原有 Python 生态实现，并在日志中给出明确提示。
Daft 版本升级到 0.7.2 之后的新版本时，接口封装层保持不变，仅需重新适配算子库 ABI。

【约束】

无

【验收场景】

参考 950 / 9755 标准性能验收环境中各产线性能用例的配置要求，逐产线执行替换前后的性能对比用例并核对执行时间。

【交付件】

1. Daft 侧集成适配源码（合入 GitCode / 蓝区代码仓）。
2. 集成后多模态产线可利用新增算子库。
3. 各产线替换前后的性能对比数据。

【DFX属性】

1. 开发者需签署《开发者原创声明》
2. 不能有工号、问题单等个人信息
3. 禁止在 Git 提交历史、CI 配置或 Issue 中硬编码 API Key、Token 等敏感信息
4. 禁止将含内部私有代码或敏感信息的分支推送到公共仓库
5. 遵守目标社区的 CONTRIBUTING.md，确保符合社区标准
6. 遵守目标社区的可靠性、可服务性要求

### 描述二：Daft 适配 Lance 算子下推

【简要描述】

Lance 作为 AI 原生列式湖存储，实现数据源侧的视频解码与抽帧能力，Daft 侧完成适配并将算子下推到 Daft 中，使解码与抽帧尽可能贴近数据源执行，减少跨边界数据搬运与中间物化，从而降低视频产线的 I/O 与格式转换开销。

【Actor】

生态开发者

【前置条件】

1. 环境配置按照鲲鹏 950 / AMD 9755 标准性能验收环境配置指南配置完成。
2. 从 GitCode 社区获取 Daft 0.7.2 源码，部署到鲲鹏 950、9755 上。
3. 获取 Lance 侧算子下推能力交付件（独立交付件），按其 Readme 完成安装部署。
4. 参考社区项目 Readme 安装 Daft 软件依赖，编译 Daft 代码，生成 wheel 文件。
5. 用户安装 Daft wheel 与 Lance 交付件，并准备视频产线性能用例与视频数据集（InternVid）。

【最小保证】

从 GitCode 获取的 Daft 源码，以及 Lance 侧算子下推能力交付件，均可在 950 环境中正常安装部署成功。

【成功保证】

用户可以正常执行视频产线的测试用例与基准测试用例，并获得正确的吞吐量与 I/O 开销数据；Lance 侧能力与 Daft 侧适配源码合入 GitCode / 蓝区代码仓。

【触发事件】

无

【主成功场景】

用户成功编译 Daft，并部署至鲲鹏 950 环境。
用户完成 Lance 侧算子下推能力的加载与 Daft 侧适配，视频解码与抽帧被下推到数据源侧执行。
用户调用 Daft，基于 InternVid 视频数据集正常执行视频产线测试用例。
统计吞吐量与 I/O 开销，算子下推前后对比，可观察到跨边界数据搬运与格式转换开销下降的自提升。

【扩展场景】

数据源不支持算子下推时，Daft 自动回退为在计算层（或 Python UDF 中）完成解码与抽帧，用例仍可正常执行。
数据源位于远端存储时，结合谓词 / 投影下推进一步裁剪读取列与行，验证 I/O 开销的额外收益。

【约束】

无

【验收场景】

参考 950 / 9755 标准性能验收环境中视频产线性能用例的配置要求，基于 InternVid 数据集执行算子下推前后的吞吐量与 I/O 开销对比用例。

【交付件】

1. Lance 侧能力与 Daft 侧适配源码（合入 GitCode / 蓝区代码仓）。
2. 算子下推前后视频产线的吞吐量与 I/O 开销对比结果。

【DFX属性】

1. 开发者需签署《开发者原创声明》
2. 不能有工号、问题单等个人信息
3. 禁止在 Git 提交历史、CI 配置或 Issue 中硬编码 API Key、Token 等敏感信息
4. 禁止将含内部私有代码或敏感信息的分支推送到公共仓库
5. 遵守目标社区的 CONTRIBUTING.md，确保符合社区标准
6. 遵守目标社区的可靠性、可服务性要求

## 延伸

### 与模板示例描述的差异

「## 模板」中给出的示例（基于 daft v0.7.5 的 make_groups / snap 优化）是 **TPC-H 性能优化** 类描述，其模块取值与本次两份输入不同：

| 模块 | 模板示例 | 描述一（多模态算子库） | 描述二（Lance 下推） |
|------|---------|----------------------|---------------------|
| 平台 | 920B vs AMD 9654 | 950 vs 9755 | 950 vs 9755 |
| Daft 版本 | v0.7.5 | 0.7.2 | 0.7.2 |
| 前置条件第 3 步 | 安装依赖并编译生成 wheel | 引入算子库独立交付件 + 编译生成 wheel | 引入 Lance 交付件 + 编译生成 wheel |
| 性能观察量 | TPC-H 平均性能达 9654 的 83% | 多模态算子处理耗时下降 | 吞吐量与 I/O 开销对比 |
| 回退要求 | 无 | 接口不可用回退原有实现 | 不支持下推时回退计算层执行 |
