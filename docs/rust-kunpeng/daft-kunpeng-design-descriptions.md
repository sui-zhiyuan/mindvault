# Daft Kunpeng 设计描述：算子插件接入与 Lance 算子下推

> 更新：2026-02-12

## 简介

本文以 `rust-kunpeng-design.md` 中的「## 模板」为固定框架，把「## 输入 1」「## 输入 2」两份需求要点分别展开为一份**完整描述**。模板中的【】项目名称与格式逐字保留，各模块下填充对应输入的实质内容（输入未给出的模块由模板框架 + 输入原文表述推导补全）。

两份描述的定位：

- **描述一** 面向 **Daft 的插件接入能力**：Daft 定义并实现算子插件接口与加载机制，外部算子库（如鲲鹏亲和多模态算子库）按该接口提供实现，用户加载插件后即可**不经 UDF** 直接像调用 Daft 原生算子一样使用其中的算子。任务范围**不含**算子库自身的实现。
- **描述二** 面向 **视频抽帧算子下推到 Lance 数据源侧**（减少跨边界搬运与中间物化）；Lance 侧能力是**前置任务**，不在本任务范围内。

Prerequisites: 环境按鲲鹏 950 / AMD 9755 标准性能验收环境配置；Daft 源码取自 GitCode 社区。Related: [Daft Kunpeng 性能优化设计](daft-kunpeng-perf-design-spec.md) / [Daft Kunpeng 总体设计需求分析](daft-kunpeng-overall-design.md)

## 核心内容

### 描述一：Daft 提供算子插件接入能力（输入 1 原始标题：Daft 适配鲲鹏亲和多模态算子库）

【简要描述】

在 Daft 侧提供算子插件接入能力：由 Daft 定义插件接口与加载机制，外部算子库（如鲲鹏亲和多模态算子库，独立仓库模式交付）按该接口提供算子实现，用户加载插件后即可**不通过 UDF**、以使用 Daft 原生算子的方式直接调用插件中的算子；插件未加载或不可用时，Daft 保持原有行为。本任务的产出仅为 Daft 侧的插件接入能力，**不含**算子库自身的实现——任何第三方只要实现该插件接口，同样可通过本任务的产出接入 Daft。

【Actor】

生态开发者

【前置条件】

1. 环境配置按照鲲鹏 950 / AMD 9755 标准性能验收环境配置指南配置完成。
2. 从 GitCode 社区获取 Daft 0.7.2 源码，部署到鲲鹏 950、9755 上。
3. 以独立仓库模式获取已按 Daft 插件接口实现的鲲鹏亲和多模态算子库插件交付件，按其 Readme 安装依赖并完成构建。
4. 参考社区项目 Readme 安装 Daft 软件依赖，编译 Daft 代码，生成 wheel 文件。
5. 用户安装 Daft wheel，加载插件，并准备视频 / 文本 / 图像 / 音频 / PDF / 智能驾驶 / LLM 预处理产线的性能用例数据集。

【最小保证】

从 GitCode 获取的 Daft 源码可正常编译、安装部署成功；在**不加载任何插件**的情况下，Daft 原有功能与行为不受影响。

【成功保证】

用户可以正常执行各多模态产线的测试用例与基准测试用例，并获得正确的执行时间；插件与 Daft 原生算子的调用方式一致，全程无需编写 UDF；Daft 侧插件接入源码合入 GitCode / 蓝区代码仓。

【触发事件】

无

【主成功场景】

用户成功编译 Daft，并部署至鲲鹏 950 环境。
用户加载鲲鹏亲和多模态算子库插件，Daft 校验其清单与版本兼容性后，把其中的算子注册进 Daft。
用户在 DataFrame 中像使用 Daft 原生算子一样直接调用插件算子，无需编写 UDF，也可与原生算子在同一 pipeline 中混用，正常执行视频 / 文本 / 图像 / 音频 / PDF / 智能驾驶 / LLM 预处理产线的测试用例。
统计执行时间，950 上插件算子调用前后对比，可观察到多模态算子处理耗时下降的自提升。
第三方实现同样的插件接口时，无需改动 Daft 即可接入其算子。

【扩展场景】

插件未加载时，Daft 自身功能完全不受影响，原有用例仍可正常执行。
插件能力缺失或部分算子注册失败时，仅该算子不可用，Daft 以明确错误或日志提示，其余算子与产线不受影响。
不同插件提供同名算子时，按插件加载顺序 / 命名空间区分，互不覆盖。
Daft 版本升级后，插件接口保持向后兼容；接口发生不兼容变更时给出明确的版本校验与提示信息。

【约束】

本任务仅覆盖 Daft 侧插件接入能力（接口定义 + 加载注册 + 调用路径），不包含鲲鹏亲和多模态算子库等外部算子库自身的实现。

【验收场景】

参考 950 / 9755 标准性能验收环境中各产线性能用例的配置要求，验证：插件可加载并通过版本校验、插件算子被正确注册、算子可被直接调用而无须 UDF、插件算子可与原生算子混用、各产线测试用例结果正确，并对比插件算子调用前后的执行时间。

【交付件】

1. Daft 侧插件接入能力源码（插件接口定义、加载注册机制、原生算子同构的调用路径，合入 Booskit 社区的 GitCode repo / 蓝区代码仓）。
2. 插件 demo：可独立构建的最小插件示例，含清单声明、算子注册与实现，配构建 / 加载说明，作为第三方实现插件接口的模板。
3. 使用插件 demo 的 demo pipeline：端到端演示「读取数据 → 调用插件算子 → 写出结果」，含与原生实现的结果一致性校验和执行时间对比。

【DFX属性】

1. 开发者需签署《开发者原创声明》
2. 不能有工号、问题单等个人信息
3. 禁止在 Git 提交历史、CI 配置或 Issue 中硬编码 API Key、Token 等敏感信息
4. 禁止将含内部私有代码或敏感信息的分支推送到公共仓库
5. 遵守目标社区的 CONTRIBUTING.md，确保符合社区标准
6. 遵守目标社区的可靠性、可服务性要求

### 描述二：Daft 适配 Lance 算子下推

【简要描述】

针对视频产线中的**抽帧算子**做算子下推：Lance 作为 AI 原生列式湖存储，已具备数据源侧的视频解码与抽帧能力，Daft 侧完成适配并把抽帧算子下推到 Lance 数据源侧执行，使抽帧尽可能贴近数据执行，减少视频数据从存储层搬到计算层的跨边界搬运与中间物化，从而降低视频产线的 I/O 与格式转换开销。本任务的依赖方是 Lance 的数据源侧能力（**前置任务**，不属于本任务范围），本任务只产出 Daft 侧的适配与算子下推。

【Actor】

生态开发者

【前置条件】

1. 环境配置按照鲲鹏 950 / AMD 9755 标准性能验收环境配置指南配置完成。
2. 从 GitCode 社区获取 Daft 0.7.2 源码，部署到鲲鹏 950、9755 上。
3. Lance 侧的数据源侧视频解码与抽帧能力已交付并可用（前置任务完成，不作为本任务交付件）。
4. 参考社区项目 Readme 安装 Daft 软件依赖，编译 Daft 代码，生成 wheel 文件。
5. 用户安装 Daft wheel，并准备视频产线性能用例与视频数据集。

【最小保证】

从 GitCode 获取的 Daft 源码可在 950 环境中正常编译、安装部署成功；在 Lance 侧能力不可用时，Daft 保持原有行为，不使用下推路径也能正常执行。

【成功保证】

用户可以正常执行视频产线的测试用例与基准测试用例，抽帧结果与下推前一致，并获得正确的 I/O 开销与执行时间数据；Daft 侧适配与算子下推源码合入 GitCode / 蓝区代码仓。

【触发事件】

无

【主成功场景】

用户成功编译 Daft，并部署至鲲鹏 950 环境。
用户完成 Daft 侧适配，视频抽帧算子被下推到 Lance 数据源侧执行。
用户调用 Daft，基于视频数据集正常执行视频产线测试用例。
统计 I/O 开销与执行时间，算子下推前后对比，可观察到跨边界数据搬运与格式转换开销下降的自提升。

【扩展场景】

Lance 侧能力不可用或数据源不支持下推时，Daft 回退为在计算层（或 Python UDF 中）完成抽帧，用例仍可正常执行。
数据源位于远端存储时，结合谓词 / 投影下推进一步裁剪读取列与行，验证 I/O 开销的额外收益。

【约束】

本任务仅覆盖 Daft 侧的适配与抽帧算子下推，不包含 Lance 侧的数据源能力实现（属前置任务），也不包含 Lance 自身的功能开发。

【验收场景】

参考 950 / 9755 标准性能验收环境中视频产线性能用例的配置要求，基于视频数据集验证：抽帧算子确实被下推到数据源侧执行、下推前后抽帧结果一致，并对比 I/O 开销与执行时间。

【交付件】

1. Daft 侧适配与算子下推源码（合入 GitCode / 蓝区代码仓）。

【DFX属性】

1. 开发者需签署《开发者原创声明》
2. 不能有工号、问题单等个人信息
3. 禁止在 Git 提交历史、CI 配置或 Issue 中硬编码 API Key、Token 等敏感信息
4. 禁止将含内部私有代码或敏感信息的分支推送到公共仓库

### 描述一的演进说明

本描述早期版本把「鲲鹏亲和多模态算子库的集成适配」写成 Daft 与某一家算子库的绑定式适配（在算子层 / UDF 路径为该库封装接口）。现按最新说明修正为**通用插件接入能力**：

| 维度 | 早期表述（已废弃） | 现行表述 |
|------|------------------|---------|
| 能力定位 | 为特定算子库封装接口 | Daft 定义通用插件接口，算子库单向适配 Daft |
| 调用路径 | 含 UDF 执行路径封装 | 不经 UDF，与 Daft 原生算子调用方式一致 |
| 任务边界 | 隐含包含算子库集成 | 仅 Daft 侧插件接入能力，不含算子库实现 |
| 受益者 | 鲲鹏亲和多模态算子库 | 鲲鹏算子库及任何实现该接口的第三方 |

### 描述一的插件接入细节（方案参考，非模板模块）

以下为把【简要描述】落到可实现层面的补充，**属于设计建议**，不作为验收硬性条款：

**接口需定义**：插件清单 / 元数据（插件名、版本、支持的 Daft 版本范围）、算子注册入口、算子签名（名、输入 / 输出类型、参数、是否支持批量）、执行契约（调用粒度、错误返回），以及可选的 CPU 能力声明（如 ARM SVE、鲲鹏 BoostKit 依赖）。

**加载与注册**：用户显式加载插件 → Daft 校验清单与版本兼容性 → 调用注册入口登记算子 → 算子进入 Daft 算子目录，与原生算子同构地参与逻辑 / 物理计划 → 用户按原生写法调用，执行时分派到插件实现。

**边界与降级**：不加载插件时 Daft 行为不变；加载失败或单算子注册失败被隔离在该插件 / 该算子内；算子不可用时明确报错，由用户显式改用原生实现，而非同一次调用内静默替换实现。

**兼容性**：插件接口带版本信息，加载阶段即校验，避免运行期出现难以定位的崩溃。

## Q&A

**Q：为什么描述一的【触发事件】仍是「无」，而【约束】不再是「无」？**
A：两份输入均不涉及事件触发式流程，故【触发事件】为「无」；而描述一的任务边界（仅插件接入能力、不含算子库实现）是明确的强约束，直接决定交付件范围，故写入【约束】。

**Q：为什么描述一必须强调「不需要 UDF」？**
A：走 UDF 意味着用户要为每个算子编写包装函数，并承担跨语言调用与序列化开销，且调用方式与原生算子不一致。插件注册到 Daft 后由物理计划直接调用，用户侧写法与原生算子相同，这也是本任务区别于「用 UDF 包裹外部库」的关键。

**Q：描述二的【触发事件】也是「无」，但【约束】不再是「无」，原因相同吗？**
A：相同。【约束】写入的是任务边界 —— 本任务只做 Daft 侧适配与抽帧算子下推，Lance 侧的数据源能力属前置任务，不重复计入本任务范围。

**Q：【DFX属性】是否两份完全相同？**
A：是。该模块属于模板固化的合规要求（原创声明、无个人信息、无敏感信息硬编码、遵守社区规范），与具体需求无关，因此逐字保留。
